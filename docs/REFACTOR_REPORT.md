# 交易基础设施重构报告

日期：2026-11-07。范围：安全边界、IBKR 适配器、行情、订单执行、确定性风控、对账、运行与验证。未启用实盘，未发送或撤销任何账户订单。

## 结论

原项目是交易基础设施骨架，不是完整 AI 量化算法。原有 243 项单元测试虽全部通过，仍遗漏了实际 SDK 签名、账户验证、行情有效期和订单幂等性等关键场景。此次保留模块化单体结构，优先修正会导致误交易、重复发送或状态失真的路径，而不是重写成更多服务。

当前默认 **PAPER + 只读 + 无生产风控授权则拒绝订单**。可做只读账户诊断、行情观察和离线回归；不具备无人值守自动交易的前置条件。

## 修复内容

### IBKR 边界

- 原先仅检查 PAPER 配置，没有验证连接实际返回的账户。现在同时等待 nextValidId 与 managedAccounts，验证 DU 模拟账户；多账户必须明确选择，非模拟账户会话拒绝。
- 新增默认只读适配器开关，覆盖下单与撤单；线上的 order.account 显式指定账户，orderRef 绑定内部 UUID。
- 修复官方 `tickSize(reqId, tickType, size)` 回调签名；接入 marketDataType 回调；修复真实 Contract.symbol 被误读成 code。
- SDK 缺失时避免重复 object 基类导致导入失败，仍可运行 API 和离线测试。
- READY 同时要求有效连接、账户验证与对账；断线使旧对账失效。reader 异常与监听器处理失败关闭交易就绪状态。
- 最终复核补上跨线程状态锁、对账取消/请求异常后的连接清理、晚完成连接的所有权与清理；账户切换不保留 READY。
- 成交 orderId 回退匹配只允许本 client，避免 Master 会话将其他 client 的成交归属到本地同号订单。非法持仓数量拒绝解析，不再折算为零风险。

### 行情

- 独立 bid/ask/last 时间戳；价格新鲜度使用双边报价中较旧的一侧。成交量、数量、最新成交不再为旧买卖价格续期。
- NaN、Infinity、无效价格、未来/无时区时间戳不再产生可执行报价；撤销某侧价格时清除旧值。
- 延迟、冻结、单边、交叉报价不可执行；订阅释放或拒绝时清除本地并发布缓存失效记录。
- 10167 归类为延迟数据警告，保留展示订阅，但绝不当作实时授权。
- API 和核心行情服务使用相同的新鲜度判断；旧缓存缺少价格时间戳时默认不可执行。

### 订单与持久化

- 先分配 IB 订单号，持久化订单标识和 PENDING_SUBMIT，再进行网络发送。传输异常记录 UNKNOWN，不能根据异常推断“没发出去”。
- 已存在的相同 UUID 不再次发送；复用 UUID 却更改订单内容会拒绝。新增 time_in_force 持久化和迁移，旧记录回填 DAY。
- 默认缺少 PreTradeCheck.authorize 时禁止新提交；在最终网络发送前再次检查授权、交易开关与连接。
- 累计成交量单调递增，晚到部分成交不覆盖已知总成交；只有 execDetails 也能更新完成状态。重复 execId 检查归属与经济字段一致性。
- 修复本地取消不落库、重复取消发送、取消异常停留 CANCEL_PENDING 等问题。操作在单个 manager 内串行化；事件通知在锁外发布，避免订阅者调用撤单时死锁。
- 行情错误码不再因为 request ID 与 order ID 碰巧相同就拒绝订单。

### 风控、对账与可观测性

- 实际执行原有但遗漏的总敞口和止损距离风险上限，拒绝缺失止损、非有限输入、非法报价时间戳和断开的 broker。
- 对已发送但 broker 未报告的 PENDING_SUBMIT、UNKNOWN、订单身份冲突、成交归属/金额冲突保持阻断。
- API 区分 gate_allows_new_orders 与实际 new_orders_allowed；陈旧 broker 心跳显示 UNKNOWN，不永远沿用旧 READY。
- 新增只读 doctor 命令，不需要数据库/Redis。修复可安装包的发现配置，Docker 镜像不再复制本地 .env/虚拟环境/数据库。

## 未实现、未证明的部分

1. **策略与 AI**：strategy / portfolio 仍没有完整算法、训练或推理链路。没有盈利能力、样本外回测或费用滑点评估证明。
2. **生产风控上下文**：没有真实 NAV/购买力快照、账户数据新鲜度、挂单风险预占。当前 worker 故意不注入放行器，不能自动下单。
3. **组合与退出**：没有完整的成交→持仓投影、持仓感知减仓规则和策略退出闭环。止损价只是风险预算输入，不代表已经在 broker 挂保护单。
4. **多进程/多账户**：仅支持单账户、固定 client ID、单 worker；manager 锁不是分布式锁，订单表未按账户/client ID 隔离。禁止多个写入者共享。
5. **恢复与运营**：没有完整自动重连 supervisor；UNKNOWN 需明确修复，不允许自动重发。只读诊断成功不等于可交易。
6. **SDK/账户检测**：DU 前缀和端口检查用于防误配置，不是 broker 官方账户类型认证；必须继续使用 TWS 模拟登录与只读权限。
7. **时间与行情**：新鲜度基于本地接收时间，不是交易所事件时间；并未证明行情授权、历史数据完整性或市场开盘时的连续流稳定性。
